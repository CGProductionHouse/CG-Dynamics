# PICASSO

Use this skill in a **local ChatGPT Work chat on the MSI Windows host**. Ask for the exact approved shoot folder, its OneDrive sync root, and a separate private job folder. Use the installed skill's `scripts/picasso.py`, or the repository's `scripts/picasso/picasso.py` when working in the checkout. Do not send originals or previews to a cloud image tool; only send minimal job counts/settings to ChatGPT unless the company approves specific image review. In the ChatGPT desktop app, local skills and local shell access must be enabled. A local filesystem skill does not prove company-wide distribution or mobile access; verify both in the intended company Work account.

## Local workflow

1. Confirm the one shoot folder, account, and intended reviewers with staff. The OneDrive connector currently sees a personal drive while the MSI has multiple sync roots; do not equate them by folder name. Pin only the selected shoot through normal OneDrive Files On-Demand if needed. Run `python <picasso.py path> preflight --input "<shoot folder>" --onedrive-root "<sync root>" --job "<private job folder>" --limit 25`. It checks metadata, online-only state and free space without reading pixels or hydrating files. If the source is a Pixieset library instead, use its normal owner download; a prior browser attempt was blocked by `ERR_BLOCKED_BY_CLIENT`, which must not be bypassed.
2. Start or resume with `python <picasso.py path> run --input "<shoot folder>" --onedrive-root "<sync root>" --job "<private job folder>" --limit 25`. Omit `--onedrive-root` only for another approved local source, such as a normal Pixieset owner export. The runner reads originals and writes `output/`, `previews/`, `contact-sheet.jpg`, and `manifest.json` in the job folder. It refuses online-only files and inadequate free space and records per-file errors without deleting originals. Repeat the same command to resume; use `python <picasso.py path> status --job "<private job folder>"` for counts.
3. Show the contact sheet and selected before/after previews to the human reviewer through local file preview. Review all `REVIEW` and `ALTERNATE` items; preserve important moments even if technically weaker. Do not present heuristic face or focus scores as verified eyes-open or expression judgments. Record human changes with `python <picasso.py path> classify --job "<job>" --id 0001 --decision KEEP --reviewer "<name>" --reason "<reason>"`. This logs the prior decision; another `classify` call can reverse it. Do not hand edit the manifest.
4. For portraits needing subtle blemish work, use the licensed Photoshop on a **duplicate output** with the person's approval. Record which output was retouched and its settings. No identity reshaping, permanent feature removal, artificial smooth skin, generative restyling, or automatic claims of blemish detection.
5. After a human **explicitly approves specific image IDs for internal review**, record `python <picasso.py path> approve-review --job "<job>" --reviewer "<name>" --ids 0001 0004 ...`. Then run `python <picasso.py path> prepare-review --job "<job>"`. This hash-checks the approved JPEGs and stages copies in the **returned** `review-upload/<approval-token>/` folder without re-encoding, uploading, publishing, or sending anything. Upload only that returned folder, never the parent `review-upload/` containing older approval batches. The approval is for internal Pixieset review only; it is not final client delivery.
6. For the requested internal review, use the official Pixieset Lightroom Classic publishing plugin when installed and configured, or staff's normal browser upload. The Lightroom plugin creates a **Preview** collection; the owner must check hidden-homepage, password, downloads, storage, filenames and count, then deliberately publish it for the named internal reviewers. Verify signed-out visitor access before copying the direct link. Use signed-in WhatsApp Web through ChatGPT Work Computer Use only when the exact **Picasso approvals** group and current audience have been verified. Post the review link and job/revision ID, not photo files or passwords in an unverified chat. For a specific amendment, run `python <picasso.py path> amend --job "<job>" --id 0001 --reviewer "<name>" --request "<verbatim feedback>" --exposure-ev 0.1` (or another bounded option shown by `--help`). This renders from the original JPEG into a new `revisions/rNNN/` folder, preserving the earlier output, and clears internal approval. Inspect the new preview; then call `approve-review --latest-revisions` and `prepare-review` again to get a distinct staging folder. Photoshop/Lightroom retouch remains a supervised manual step. Never automatically release a client gallery, scrape Pixieset/WhatsApp, use unofficial endpoints, or invent an API. The Pixieset Photo Editor may require Pro or generative credits; do not assume it satisfies R0.

## Editor choice

The host audit in `docs/ops/PICASSO-LOCAL-EDITOR-2026-10-25.md` is the current baseline. Adobe-signed Lightroom Classic **15.6** now opens on the MSI with an empty catalog and an Assisted Culling panel; actual culling, activation and plugin publishing have not been exercised. Prefer its Assisted Culling, saved presets, masking, and batch export when proven on an approved shoot. Photoshop 2026 is available for supervised retouch. The bundled Python/OpenCV/Pillow runner is a narrow local first pass using installed libraries, not a replacement for Lightroom's review controls. Do not install multiple editors or LightCraft speculatively. `digiKam` culling and `darktable-cli` are optional mature free paths only after a specific quality gap is established and their Windows builds are reviewed.

## Quality and privacy gates

- Only existing JPEGs. Preserve original bytes, dimensions and orientation; output one sRGB-tagged JPEG encode at high quality. An untagged input is **assumed** sRGB and flagged for review.
- Exposure, face luminance, clipping, cast, and focus are heuristics. Never promise recovery of clipped JPEG data. Keep warm atmosphere and natural skin. The first pass does no automatic skin retouch and does not detect open eyes or expression.
- The job manifest, previews, originals, client names, and EXIF stay in private local storage. The exported JPEGs omit source EXIF/GPS. Do not commit or paste client media or private file paths into GitHub.
- Stop at the 25 approved-sample human quality gate. Run 100 and then 1,000 only after the reviewer approves the smaller batch. Report measured time, versions, errors, quality findings, and R0 incremental spend. Never claim everyday ChatGPT invocation until a user actually runs this skill from ChatGPT Work.
