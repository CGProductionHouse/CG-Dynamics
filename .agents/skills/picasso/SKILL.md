# PICASSO

Use this skill in a **local ChatGPT Work chat on the MSI Windows host**. Ask for the exact approved shoot folder, its OneDrive sync root, and a separate private job folder. Use the installed skill's `scripts/picasso.py`, or the repository's `scripts/picasso/picasso.py` when working in the checkout. Do not send originals or previews to a cloud image tool; only send minimal job counts/settings to ChatGPT unless the company approves specific image review. In the ChatGPT desktop app, local skills and local shell access must be enabled. A local filesystem skill does not prove company-wide distribution or mobile access; verify both in the intended company Work account.

## Local workflow

1. Confirm the one shoot folder, account, and intended reviewers with staff. The OneDrive connector sees a delegated drive while the MSI has multiple sync roots; do not equate them by folder name. Pin only the selected shoot through normal OneDrive Files On-Demand when its Windows sync identity matches. When sync fails, use the authorized Microsoft SharePoint connector to list the exact folder and fetch only selected approved JPEGs to a private local source folder. Compare every local byte count and SHA-256 with the connector's file metadata before editing; keep OneDrive item IDs and source provenance private. Never expose short-lived download URLs, crawl an entire library, or treat a filename alone as shoot provenance. Run `python <picasso.py path> preflight --input "<shoot folder>" --onedrive-root "<sync root>" --job "<private job folder>" --limit 25`; omit `--onedrive-root` for a verified private connector copy. Preflight checks local metadata and free space without reading pixels. If the source is Pixieset itself, use its normal owner download; a prior browser attempt was blocked by `ERR_BLOCKED_BY_CLIENT`, which must not be bypassed.
2. Start or resume with `python <picasso.py path> run --input "<shoot folder>" --onedrive-root "<sync root>" --job "<private job folder>" --limit 25`. Omit `--onedrive-root` only for another approved local source, including a SHA-256-verified private copy obtained from the authorized OneDrive connector when the mapped Windows sync account is unavailable. The runner reads originals and writes `output/`, `previews/`, `contact-sheet.jpg`, and `manifest.json` in the job folder. It refuses online-only files and inadequate free space and records per-file errors without deleting originals. Repeat the same command to resume; use `python <picasso.py path> status --job "<private job folder>"` for counts and `python <picasso.py path> verify --job "<private job folder>" --quality` for read-only hash, JPEG, dimensions, sRGB, EXIF and bright-pixel comparison. A bright-pixel threshold is a review signal, not proof of photographic quality. Never paste signed media download URLs into a chat or log.
3. Show the contact sheet and selected before/after previews to the human reviewer through local file preview. Review all `REVIEW` and `ALTERNATE` items; preserve important moments even if technically weaker. Do not present heuristic face or focus scores as verified eyes-open or expression judgments. Record human changes with `python <picasso.py path> classify --job "<job>" --id 0001 --decision KEEP --reviewer "<name>" --reason "<reason>"`. This logs the prior decision; another `classify` call can reverse it. Do not hand edit the manifest.
4. For portraits needing subtle blemish work, use the licensed Photoshop on a **duplicate output** with the person's approval. Record which output was retouched and its settings. No identity reshaping, permanent feature removal, artificial smooth skin, generative restyling, or automatic claims of blemish detection.
5. After a human **explicitly approves specific image IDs for internal review**, record `python <picasso.py path> approve-review --job "<job>" --reviewer "<name>" --ids 0001 0004 ...`. Then run `python <picasso.py path> prepare-review --job "<job>"`. This hash-checks the approved JPEGs and stages copies in the **returned** `review-upload/<approval-token>/` folder without re-encoding, uploading, publishing, or sending anything. Upload only that returned folder, never the parent `review-upload/` containing older approval batches. The approval is for internal Pixieset review only; it is not final client delivery.
6. For the requested internal review, use the official Pixieset Lightroom Classic publishing plugin when installed and configured, or staff's normal browser upload. The Lightroom plugin creates a **Preview** collection; the owner must check hidden-homepage, password, downloads, storage, filenames and count, then deliberately publish it for the named internal reviewers. Verify signed-out visitor access before copying the direct link. Use signed-in WhatsApp Web through ChatGPT Work Computer Use only when the exact **Picasso approvals** group and current audience have been verified. Post the review link and job/revision ID, not photo files or passwords in an unverified chat. For a specific amendment, run `python <picasso.py path> amend --job "<job>" --id 0001 --reviewer "<name>" --request "<verbatim feedback>" --exposure-ev 0.1` (or another bounded option shown by `--help`). This renders from the original JPEG into a new `revisions/rNNN/` folder, preserving the earlier output, and clears internal approval. Inspect the new preview; then call `approve-review --latest-revisions` and `prepare-review` again to get a distinct staging folder. Photoshop/Lightroom retouch remains a supervised manual step. Never automatically release a client gallery, scrape Pixieset/WhatsApp, use unofficial endpoints, or invent an API. The Pixieset Photo Editor may require Pro or generative credits; do not assume it satisfies R0.

## Editor choice

The host audit in `docs/ops/PICASSO-LOCAL-EDITOR-2026-10-25.md` is the current baseline. Adobe-signed Lightroom Classic **15.6** opened on the MSI with an empty catalog and Assisted Culling panel, but its import chooser became unresponsive; actual culling, activation and plugin publishing have not been exercised. Prefer its Assisted Culling, saved presets, masking, and batch export when proven on an approved shoot. Photoshop 2026 is available for supervised retouch. The bundled Python/OpenCV/Pillow runner is a narrow local first pass using installed libraries and an MIT-licensed, pinned local OpenCV YuNet face detector model; it never downloads a model or identifies people. It is not a replacement for Lightroom's review controls. Do not install multiple editors or LightCraft speculatively. `digiKam` culling and `darktable-cli` are optional mature free paths only after a specific quality gap is established and their Windows builds are reviewed.

## Quality and privacy gates

- Only existing JPEGs. Camera `.JPG` files identified by Pillow as two-frame MPO are accepted using the primary frame only; the manifest records the container and frame count. Preserve original bytes, primary-frame dimensions and orientation; output one sRGB-tagged JPEG encode at high quality. An untagged input is **assumed** sRGB and flagged for review.
- Exposure, face luminance, clipping, cast, focus and similarity are heuristics. A similarity hint can accompany REVIEW without changing its classification. The bright-source-channel guard reduces newly clipped highlights; it cannot recover already clipped JPEG data. Keep warm atmosphere and natural skin. The local YuNet model found face **candidates** in 18/25 mixed images and flags three possible backlit-face scenes for human review. These are not verified identities, expressions or skin assessments; missing candidates do not prove no face exists. The first pass does no automatic skin retouch and does not detect open eyes or expression. If the pinned face model is unavailable, the manifest records that and sends images to REVIEW.
- Exported sRGB ICC data uses a fixed creation date so the same source and settings produce byte-identical JPEGs across separate jobs. A real-photo repeat matched its prior output SHA-256. Keep the model, settings and runner version with the manifest when reproducing a job.
- The job manifest, previews, originals, client names, and EXIF stay in private local storage. The exported JPEGs omit source EXIF/GPS. Do not commit or paste client media or private file paths into GitHub.
- Stop at the 25 approved-sample human quality gate. A 25-image single-scene technical run does not satisfy varied-lighting or human acceptance. Run 100 and then 1,000 only after the reviewer approves a varied 25-image batch. Report measured time, versions, errors, quality findings, and R0 incremental spend. Never claim everyday ChatGPT invocation until the skill actually runs from ChatGPT Work. The Computer Use skill prohibits automating ChatGPT's own desktop UI, so Codex cannot simulate that invocation.
