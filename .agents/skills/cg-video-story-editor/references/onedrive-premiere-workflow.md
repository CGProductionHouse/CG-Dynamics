# Repeatable media-to-Premiere handoff

1. Resolve the exact OneDrive account and drive before transfer. The Bloem case uses the `info@cgproductionhouse.com` personal OneDrive, distinct from the company drive. Record the drive ID. A connected OneDrive API may cap a download at 100 MiB; this is a connector limit, not a reason for staff to hand-download assets.
2. With the account owner's authorization, configure rclone's OneDrive backend as read-only using `Files.Read` and `offline_access`. Do not enable `disable_site_permission=true` for this configuration: rclone's OAuth helper then substitutes broader default scopes. Review the generated consent URL and confirm the signed-in account. Store tokens in the machine's protected rclone config only, outside project files.
3. Copy original media by exact path. Compare remote and local size and SHA256 where metadata is available. Retain original filenames and keep a source ledger with rights and prior-use fields.
4. Probe the clips, watch them, and select in/out points. Generate an edit manifest. A scripted review render and FCP7 XML can fast-track assembly, while Premiere remains the creative editing surface. For FCP7 XML on Premiere Pro 2026 for Windows, the Bloem case required `file://localhost/C%3a/...` media paths, matching Premiere's own XML export. Do not declare an audio stream on video-only MP4 or PNG files; Premiere rejects the relink as a media-type mismatch. Import corrected XML into a clean project when previous attempts created offline clip records. Confirm online picture, titles, licensed music, and brand sound in the program monitor before saving the `.prproj`.
5. For staff deployment, install only this skill and its references on each machine. Each employee should authenticate their own permitted drive access through the approved account process. Never distribute the original machine's `rclone.conf`, OAuth token, or licensed media files as part of the skill.
