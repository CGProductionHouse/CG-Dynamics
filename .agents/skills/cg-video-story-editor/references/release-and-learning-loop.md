# Final release and learning loop

Every client video is a creative decision and a small test of a buyer hypothesis. Package the edit so a teammate can publish it, reopen it for feedback, and use its results to make the next one sharper.

## Before final export

1. Record the exact client, buyer, message, proof, action and one testable hypothesis. Read that client's current CG Dynamics guide and relevant plan; check recent actual posts and their covers. Mark what was seen and what was not available. An empty dated Client Schedule does not prove no video was planned.
2. Lock the actual client-approved story and screen the complete moving export at phone size with audio. Inspect every transition, person/performance, product detail and brand outro. For a prior approved animation, inspect the source's **first beat, full construction, reveal, settled mark and final frame** before trimming it. A portrait reframe must keep the mark legible and the animated thought complete; fade or resolve the visual tail with the music. Sound from the source can be omitted if the film's score resolves better on its own. A rendered proxy or static contact sheet is insufficient sign-off.
3. Save and reopen or inspect the final native Premiere project. Confirm media online, sequence name, portrait resolution, separate editable picture/title/audio tracks and the final shot. Record baked treatments and their source recipes. Use a new versioned render path so Premiere does not cache an older revision.
4. Run objective media checks: frame count, CFR, dimensions, full decode, audio loudness and true peak. These checks support, but never replace, the moving and listening review.

## One delivery package

**Filename gate before any review upload:** read `C:\Projects\CG-Dynamics\docs\onedrive-naming-authority.md`, the exact client's existing production folder/export names and the current CG Dynamics video identity. The canonical production prefix is `YYYY_MM_<CONFIGURED_CLIENT_SHORT_CODE>_VIDEO_<XX>`; `XX` is zero-padded and neither the code nor sequence may be inferred from the display name. Preserve the established descriptive stem where one already exists. Give protected review revisions a unique suffix, and compare the actual WhatsApp document filename with the expected production identity *before pressing Send*. A technically correct render with an ad hoc `CLIENT-STUDIO-V8-REVIEW` basename fails the handoff gate. Do not overwrite an existing final to repair the name; copy to a protected, versioned path and verify its hash. A missing or ambiguous canonical identity is a blocker to naming and OneDrive filing, never a reason to invent a folder.

Use the client's confirmed naming convention. Put approved finals in the exact client `Final Video Exports` folder on local storage and the approved client OneDrive destination:

- `{final-stem}.mp4`: one unambiguous final export.
- `{final-stem}_COVER.png` or `.jpg`: a clean frame-led 1080 × 1920 image. Compare the client's current Reel cover grid and Canva cover collection, not poster designs. Check centered 4:5, 3:4 and square crops. Keep all critical content in the 4:5 region. Do not recycle a published cover.
- `{final-stem}_CAPTION.txt`: final caption, researched against current client voice, recent social copy, verified contacts and the edit's objective. Add a human prompt only when it fits the story. Avoid claiming illustrative stock is the client's completed work.
- `{final-stem}_RELEASE.md`: audience, arc, test hypothesis, evidence links, media/licensing and reuse notes, project path, technical QA, unresolved release gates, and month-end review plan.

Keep the editable Premiere `.prproj`, interchange/manifest, source selects and licence evidence in the edit workspace. Do not fill the final folder with draft exports. Replace only the exact final file when a new approved revision is ready, then verify the cloud file sizes and names.

For the **CG Nolan Approvals** internal WhatsApp handoff, keep the two media messages forwardable without editing: send the MP4 as a document with **only the complete proposed post caption in that same message**, then send the approved cover **alone as an HD image**, without any note or caption on the image. Put review questions, release gates and other internal context in a separate third message signed from Nolan. Inspect the sent message types and delivery status; a JPG sent as a document is not the requested image handoff. Never treat an internal review send as client approval. If an owner rejects a cover, preserve it as rejected evidence and make a fresh cover audit before resending a corrected pair.

## Dynamics and publication

Record client-specific final direction and the test in that client's authorised CG Dynamics context with the OneDrive destination and source notes. This is an append-only client update; it does not rewrite the canonical Content Guideline. Only change a Content Run guideline in its authorised staff context. Link an existing scheduled deliverable when its durable ID is actually known; never invent a client or schedule ID.

Before publishing, have the team confirm original-footage permissions, prior-use decisions, client/brand approval and the real Instagram cover preview. Record actual posting date, platform, final caption and cover. Do not call a local technical export a published/approved asset.

## After the month closes

Use Meta Business Suite for the released Reel and comparable recent client Reels with the same observation window. Capture distribution (reach/impressions), initial hold if available, average watch time and retention/completion, replays, saves, shares, comments, profile visits, contact actions and qualified enquiries. Read the comments and DMs for actual buyer language. Compare rates alongside totals and audience size; views alone cannot prove the film's hook or concept worked.

Write what was observed, which edit moment lost viewers, what business signal appeared, and the one change to test next. Feed verified, client-specific findings into that client's kit/plan and only promote genuinely reusable, verified editing lessons into this skill. Preserve the original creative hypothesis even if results disagree with it.
