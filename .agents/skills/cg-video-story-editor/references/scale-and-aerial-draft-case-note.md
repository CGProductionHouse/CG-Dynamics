## Source pattern

The WhatsApp upload contained nine distinct 848 × 478 landscape drone videos and sixteen distinct aerial photographs. Several photos depict visibly different arrays and locations. Treat such a package as a portfolio montage unless site identity or a true chronology is verified. Never turn clips of multiple sites into a fake build progression. The separate residential package promotion in the same group did not establish specifications for these arrays.

Screen each drone shot for the **seconds during which the subject stays in frame**, not just the best still. In this draft, a 120-second flight yielded a useful 2.4-second construction overview near its start; a mid-flight range drifted onto bare land while the words “build the whole system” were on screen, so the select was moved back to the array. Record accepted in/out and rejected neighboring movement. Give every selected shot a distinct visual job: steelwork, forward panel pass, sun glint, low structural view, overhead pattern, full site reveal. A new file is not automatically a new visual idea.

Choose the output ratio from the source and the proof. The array scale was legible in 16:9; portrait cropping would throw away the rows and site layout. WhatsApp compression limits what sharpening can recover; moderate 720p upscale is preferable to aggressive zoom or fake detail. Do not equate a higher export number with more source detail.

Put the essential sentence on a separate, unobstructed layer so the mask cannot make the copy unreadable. Inspect start, middle and final frame for a drifting edge. A screenshot of one frame is insufficient. The first JFJ draft uses a short corridor segment where panel geometry stays stable; this mask is a precomp, with its clean source and generator kept for revision.

Check final frame count, constant frame rate, loudness and true peak. Measurement cannot decide whether the music *sounds* right; a person must listen before release. Use an effect only when its peak supports a visible moment such as the first wide reveal.

## Draft 04 | frame repair test and a shorter motion arc

The owner asked for more visible craft and suggested added frames or frame blending for glitchy footage. A dense sample of the forward-array source around 9.2–10.0 seconds showed a sustained soft/blurred section. A short FFmpeg optical-flow test reproduced the softness; invented in-between frames could not recover sharp source detail. The edit therefore leaves that section out. This is a **source-select problem first**, not a universal interpolation fix. Adobe distinguishes frame blending (averaging adjacent frames) from optical flow (motion-estimated in-betweens) in its [Premiere time-interpolation guide](https://helpx.adobe.com/ca/premiere/desktop/edit-projects/change-clip-speed/apply-time-interpolation-methods-to-adjust-clip-speed.html).

Draft 04 tests interpolation where it has a defensible job: a clean section of the forward flight from 6.0–8.42 seconds is converted to a dense temporary and mapped through one continuous eased slow-to-fast curve. The source index never reverses; the map is saved with the processed clip. Inspect the full moving output for bent panel lines, ghosting, repeated frames and crop drift. Keep the normal-speed select if the ramp feels invisible or artificial. The current treatment is baked in the Premiere XML, with the source range and generation recipe preserved for revision.

The 15-second cut gives five short distinct picture beats to the buyer question, a longer forward-aisle breath, a real site reveal, construction scale, the retimed clean pass and a moving site close.
