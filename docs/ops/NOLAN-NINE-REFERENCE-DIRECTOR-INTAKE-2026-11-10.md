## Actual implementation and tests

A new `reference_director.py` prototype extends the SAME existing story plan with a `director` section. It is not a renderer or a parallel client database. Source code and tests are staged, not silently installed into the active core.

The source model separates owner annotations, creator descriptions, auto-captions, visual observations and audio observations. Observations must bind available evidence. A technique cannot be marked qualified without its actual implementation, positive control, negative control, encoded-output review and test evidence; visual/sound replication requires the respective source review.

The director validator checks the original client audience, message, objective, proof and action; three distinct staged openings; a chosen-hook rationale; a decision for each original shot; why an effect helps and why not a plain cut; the actual existing skill/card binding; meaningful rhythm and ending; retained positive feedback; source-backed relevant trends or a justified evergreen choice; and the picture/sound comparison plan. It allows purposeful clean cuts. Voice-led work requires voice source/consent, script, pronunciation, phrase-picture map and ducking plan. Stock cannot masquerade as actual client premises.
