Owner: [#878](https://github.com/CGProductionHouse/CG-Dynamics/issues/878). Implementation under review: [draft PR #879](https://github.com/CGProductionHouse/CG-Dynamics/pull/879). This plan extends the [local editor audit](PICASSO-LOCAL-EDITOR-2026-10-25.md). It is research and a test sequence, not a claim that the complete workflow works today. The owner's R0 additional-spend, private-media, no-new-hosting, and Nolan #862 boundaries remain in force.

## Intended staff experience

An authorized staff member tells **company ChatGPT Work**: “PICASSO, take the approved shoot in this OneDrive folder, prepare a private review, and show me the cull and edits.” PICASSO resolves the exact folder and job ID, confirms the files are available on the MSI, runs local analysis and editing, and presents a contact sheet plus exceptions. After the photography quality gate, the staff member authorizes an internal Pixieset review collection. PICASSO checks its privacy settings and posts the review link to the existing **Picasso approvals** WhatsApp group. Reviewers identify specific filenames and changes; PICASSO creates a new revision, QC checks it, republishes only approved replacements, and posts a revision note. Final client release remains a separate staff decision.

The approval-group post is an internal review handoff. It must never be treated as authorization to send a client gallery, change client-facing access, or delete originals.

## Narrow workflow to implement and prove

1. **Intake.** Staff chooses one approved OneDrive shoot folder and confirms the owner/client and intended internal reviewers. PICASSO records its canonical OneDrive item identity, sync account, local path, source file count, total size, estimated working space, and immutable source hashes. Pin only that folder in OneDrive; check every JPEG is locally available before starting. Do not recurse through all `Clients` or hydrate multi-terabyte libraries. Block if the OneDrive connector identity and MSI sync identity do not match the source.
2. **Private job.** Create `job-id/input-reference`, `manifest.json`, `previews/`, `revisions/r01/`, and `exports/` outside the synced source folder. Originals stay read-only. Record tool versions, colour profile, orientation, hashes, cull decisions, settings, errors, and review author. Use a per-job size quota and leave room for originals, Lightroom previews/catalog, revision masters, and final JPEGs. No automatic deletion.
3. **Cull and finish.** Use Lightroom Classic Assisted Culling with non-destructive Pick/Unflagged/Review decisions and inspect burst stacks manually for documentary value. Run scene groups separately (backlit, daylight, mixed warm, low light, already good). Apply approved presets/AI masks conservatively, inspect face/skin and clipped channels, and export sRGB high-quality JPEG once per approved revision. Use Photoshop only on duplicate masters for specific temporary blemishes. If Lightroom automation via Computer Use proves too fragile, keep the runner as an advisory first pass and let staff finish in Lightroom. The Lightroom SDK is mainly an extension point for export, publish, metadata and UI, not evidence of a supported unattended Develop/AI-culling API. [Adobe Lightroom Classic SDK](https://developer.adobe.com/lightroom-classic).
4. **Local QC gate.** Show contact sheet, before/after pairs, REVIEW/ALTERNATE reasons, failure count, dimensions, colour space and EXIF status. Staff approves which files may leave the local job. The 25-photo varied-lighting test precedes 100 and 1,000. Do not upload all culls or private working files.
5. **Internal Pixieset review.** Staff authorizes a new, clearly named **internal review** collection. Lightroom plugin or normal owner browser uploads the approved exports. Confirm image count and filenames, collection status, hidden homepage, password, download settings, watermark if desired, and storage. The plugin's Preview result is then deliberately published for the named internal reviewers. Verify a signed-out visitor can view only the intended collection with its password, then capture its direct link. Keep final client gallery separate until final signoff.
6. **Approval-group post.** In the already signed-in WhatsApp Web account, verify the group title and current membership with staff. Prepare a compact message containing job ID, revision, collection link, count, deadline if supplied, and an instruction to cite filenames or use Pixieset Favorite Notes. Confirm exact recipient and link privacy at send time. Post one message, then verify it appears in the intended group. Do not use browser DOM scraping, reverse-engineered endpoints, or an unofficial WhatsApp automation package.
7. **Amendments.** Turn feedback into a change list keyed by image filename/manifest ID, reviewer, requested edit, and decision. Ask for clarification when feedback is vague or conflicts with identity/skin constraints. Make revisions from original or Lightroom edit state, never from an already JPEG-encoded export. Save new revision outputs and a diff/contact sheet. Staff QC approves each changed image; use Pixieset republish or controlled replacement, verify no unexpected removals/duplicates, and post a revision summary to the same group. Record explicit final internal approval before separate client delivery.

## Gates and tests in order

1. **Access gate:** finish Lightroom Classic installation and record exact version; install and authenticate official Pixieset `1.0.4` plugin; prove company ChatGPT Work can select `@picasso` and execute a status command on the MSI; identify matching OneDrive account and local folder; verify scoped access to WhatsApp group. No client media goes to a hosted photo editor.
2. **25 JPEG gate:** approved varied-lighting OneDrive shoot with actual local bytes; cull and edit; staff evaluates natural skin, preserved atmosphere, focus choices and documentary moments; compare Lightroom versus the existing runner; demonstrate private job resume and error handling. Record runtime and remaining free disk.
3. **Review-link gate:** upload only approved 25-sample exports to an internal Pixieset review collection, verify all privacy settings and visitor access, send the link to the exact Picasso approvals group, and verify message delivery. Keep the client-facing collection separate.
4. **Revision gate:** a reviewer names one or more photos and specific edits. Re-edit from the non-destructive source, republish, verify changed images and unchanged others, then post an amendment receipt.
5. **Scale gate:** after human quality acceptance, run 100 then 1,000 JPEGs with measured hydrate time, culling/edit/export/upload duration, failure recovery, free-space high-water mark, and no new spend.

## Explicit unresolved items

- Company-wide ChatGPT Skill/plugin sharing, Work local-computer permission, account roles and iOS remote access have not been tested. Workspace distribution must not be inferred from one MSI skill folder.
- The OneDrive connector currently resolves a personal drive. Confirm which tenant/account owns each real shoot and which local sync root maps to it; no bulk OneDrive media download has been performed.
- WhatsApp group membership, browser session access, exact send permission, and feedback read path remain unverified. No official connected WhatsApp/Pixieset plugin was found in the available plugin directory search; more may appear later.
- Pixieset plugin publish, internal private review settings, signed-out access and replacement/republish behavior need real acceptance tests. The earlier `downloads.pixieset.com` block matters for Pixieset-as-*source* samples; OneDrive-source tests can proceed independently.
- The initial brief's no-auto-publish rule remains the default. The requested internal approvals-group workflow is a named, authorized review exception after local QC. No automated client release.

## R0 decision

Use **ChatGPT Work + a scoped PICASSO skill + MSI OneDrive sync + Lightroom Classic/Photoshop + official Pixieset Lightroom plugin + signed-in WhatsApp Web Computer Use**. Add no hosted application, photo API, WhatsApp Business Platform subscription, gallery scraper, or speculative editor. A private workspace skill/plugin is a distribution option only if local Work proof succeeds and the workspace administrator authorizes the role and device access.

## Local implementation checkpoint

The isolated PR now adds `preflight` to the private runner. It counts the selected JPEGs, checks explicit OneDrive-root containment, identifies Windows online-only placeholders without hydrating them, and checks free space before reading media. `run` refuses a non-ready shoot. After the human inspects the contact sheet and names approved IDs, `approve-review` records an internal-review-only, hash-bound selection. `prepare-review` stages exact copies of only those exports in `review-upload/`; it never uploads or sends them. Resume retains approval only while the selected output hashes and classifications still match. Five local tests passed, including placeholder refusal without media reads and refusal to stage a changed export. These are local safety mechanics, **not** a proof of OneDrive account mapping, photo quality, ChatGPT Work invocation, Pixieset upload, WhatsApp posting or amendment handling.
