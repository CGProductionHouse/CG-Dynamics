# Staff SOP — monthly designed-poster production

Last updated: 2026-09-09

## Goal

Give CG staff one repeatable process for producing a whole month's designed posters (`DP`) whether the final creative is generated by ChatGPT or designed manually.

The system must remain useful even when AI is skipped. The same strategy, source, naming, freshness, approval and tracking rules apply to human-built posters.

## Before you start

Work from the exact client project/chat and exact CG Dynamics month/package.

Never begin by opening Canva and designing "something" because a poster is due.

### Required truth

- exact client;
- exact month;
- exact package/static deliverable slots;
- canonical content type (`DP`, `F`, `Video`, `Reel`);
- exact client short code;
- relevant brand scope/sub-brand;
- current client strategy/restrictions;
- previous month/creative history;
- current OneDrive media;
- relevant Canva history.

## Phase 0 — monthly creative planning

A staff member may start with a short written brief or voice note, e.g.:

> We need November Piek Group Engen posters. I have an idea around Bloem getting warmer and road trips.

ChatGPT then does the heavy planning work:

1. resolve the exact Dynamics month/package;
2. read prior strategy/client feedback;
3. inspect the correct brand-scope Canva history;
4. inspect recent content/media usage;
5. inspect fresh OneDrive media;
6. research current local/seasonal/category context where useful;
7. decide the monthly marketing mix;
8. assign each concept to a real DP slot;
9. define strategy before copy/design;
10. select source media;
11. prepare the monthly production pack.

Do not force every poster to be a campaign. Do require every poster to have a reason to exist.

## Phase 1 — canonical identity

Every designed poster follows:

`YYYY_MM_CLIENT_DP_XX`

Example:

`2026_11_PIEK_DP_01`

`XX` maps to the Dynamics monthly deliverable instance. The immutable Dynamics ID is stored separately.

Sub-brand is separate metadata:

`brand_scope = ENGEN`

Optional descriptive filename:

`2026_11_PIEK_DP_01__ENGEN_SUMMER_PLANS.png`

Staff should not invent names. The long-term Dynamics implementation should generate these automatically.

## Phase 2 — source selection and freshness

Before selecting a photo, check:

- exact photo already used?
- near-identical burst/crop already used?
- same person used too recently/often?
- same product/service/topic overused?
- same visual angle/shoot overused?
- same creative mechanism repeated?

Prefer fresh real client-owned media.

A repeat is acceptable only with a reason: client request, campaign necessity, seasonal relevance, enough time passed, or a genuinely fresh reinterpretation.

## Phase 3 — professionally prepare selected source

Raw/original stays in the normal Photos library.

Create a non-destructive production derivative in:

`Posters/<YYYY>/<YYYY_MM_MON>/01_SOURCE_EDITED/`

Example:

`2026_11_PIEK_DP_01__SRC_EDITED_01.png`

The edited source should already be pleasant enough that a designer can immediately use it.

Allowed photographer-grade correction:

- exposure/highlight/shadow;
- white balance/colour;
- tasteful contrast/clarity/sharpness;
- crop/straighten;
- lens/perspective where needed;
- temporary blemish/fresh scratch/redness cleanup;
- cutout/background cleanup where conceptually required.

Never change identity-defining human features.

## Phase 4 — build the monthly Chat Pack

The month is prepared as one batch where practical.

`02_CHAT_PACK/` contains:

- `CHAT_ATTACH/` — actual edited source files + exact logos + exact relevant style-reference screenshots;
- prompt text;
- manifest;
- portable ZIP.

Do not mix style references across sub-brands.

Examples:

- Engen -> Engen references only;
- Get Together -> Get Together references only;
- Sasol -> Sasol references only;
- Piek corporate -> Piek corporate references only.

The references are inspiration, not templates.

## Phase 5 — generate the month's Wave 1

In normal ChatGPT browser chat:

1. attach the month's required `CHAT_ATTACH` images;
2. paste/use the exact monthly generation prompt;
3. generate the planned batch;
4. save viable first candidates into `03_WAVE_1` with their exact DP IDs.

The objective is not "ten versions of one template". Each poster is individually art-directed but belongs in the same brand family.

Review every poster at phone size and review the whole month together as an Instagram grid.

Wave 1 is internal CG review, not client approval.

## Phase 6 — amendment decision tree

This is important. Do not automatically tell ChatGPT "change this" on the same generated image.

### Problem A — production correction

Examples: wrong logo, typo, wrong exact font, text size, spacing, brand colour, small alignment/layout nudge.

**Action:** fix in Canva/Adobe. Do not regenerate.

### Problem B — source-photo correction

Examples: face too dark, crop wrong, exposure/colour needs work, temporary blemish, cutout needs cleanup.

**Action:** return to the original selected source. Edit that source non-generatively. Recompose only if needed.

### Problem C — concept/composition is wrong

Examples: boring, generic AI, template-like, wrong hierarchy, wrong emotion, visual idea misses the brief.

**Action:** reject only that DP. Keep accepted DPs locked. Reattach the exact original edited source + exact logo/reference pack + revised strategy prompt and generate that DP again from scratch.

Do not use the previous generated poster as the sole input unless deliberately preserving its composition is necessary and there is no human-identity risk.

### Problem D — minor effect tweak

If Canva/Adobe can change it cleanly, do that rather than forcing a new generation.

## Phase 7 — final production

Move approved creative to `05_APPROVED`.

Use Canva/Adobe for:

- exact typography;
- exact original client/partner logo;
- safe production corrections;
- editable team handoff;
- final export variants.

Canva Magic Layers/image-to-design may be used to make a strong flat AI/external design editable. It is a finishing route, not the primary creative brain.

## Phase 8 — link back to Dynamics

The final DP must resolve to the exact canonical monthly deliverable.

Record/retain:

- `monthly_deliverable_id`;
- stable production ID;
- client/month/code/instance;
- brand scope;
- scheduled date;
- strategy version;
- original source OneDrive ID;
- edited-source OneDrive ID;
- usage/repetition tags;
- candidate/amendment history;
- exact Canva design + page;
- approval state;
- schedule/publish reference;
- later performance/learning.

Do not create a second social calendar. `monthly_deliverables` remains schedule truth.

## Phase 9 — next month

Do not start over.

Read:

- what we planned;
- what was approved/rejected;
- which photos/people/products/services were used;
- client feedback;
- what was boosted/paid-supported;
- relevant Meta/platform performance;
- what performed or failed strategically;
- current season/context.

Then continue.

The first client bootstrap is the expensive setup. Every later month should become faster and smarter because the system already knows what happened.

## Minimum QA gate

Do not send a poster forward merely because it rendered.

Reject if any of these are true:

- weak/generic/meaningless headline;
- no clear audience or marketing purpose;
- wrong or fake client truth;
- wrong/recreated logo;
- identity-altered real person;
- unreadable phone typography;
- repeated photo/person/service without reason;
- design looks like PowerPoint/Word/stock Canva;
- design feels obviously AI-generated;
- same template skeleton repeated across the month;
- monthly grid clashes or becomes monotonous;
- work is below CG Production House's own visual standard.

The expected result is not merely usable. The system should make above-standard work the normal outcome.
