# Monthly Chat Pack production contract

Last updated: 2026-09-09
Status: launch-now interface between CG Dynamics/OneDrive planning and normal-browser ChatGPT image generation.

## Why this contract exists

The Chat Pack is the handoff boundary that makes the graphic-design workflow repeatable for staff today, while remaining replaceable when direct Dynamics/OneDrive image-reference generation improves.

A staff member should not need to explain the client again inside the image-generation chat. The planning system must package the correct strategy, exact assets and explicit source-to-poster mapping first.

## Canonical batch identity

A Chat Pack belongs to one:

- client;
- deliverable month;
- brand scope (or a clearly separated multi-scope batch when explicitly required);
- package version.

Example:

`2026_11_PIEK_CHAT_PACK_v02.zip`

The ZIP is not a content deliverable. Individual posters retain their own exact stable production IDs such as:

`2026_11_PIEK_DP_01`

## Required files

```text
02_CHAT_PACK/
  CHAT_ATTACH/
    SOURCES/
    LOGOS/
    STYLE_REFERENCES/
    OPTIONAL_SUPPORT/
  PROMPT.txt
  MANIFEST.csv
  QA_NOTES.txt
  <YYYY_MM_CLIENT>_CHAT_PACK_vNN.zip
```

The portable ZIP mirrors these files. In current normal-browser ChatGPT, staff should still attach the actual images from `CHAT_ATTACH` so the image generator receives them as surfaced visual references.

## `SOURCES/` contract

Only professionally prepared production derivatives go here.

Filename:

`YYYY_MM_CLIENT_DP_XX__SRC_EDITED_NN.png`

Rules:

- linked to canonical original OneDrive item ID in the manifest;
- professionally colour/exposure/crop corrected before generation;
- real-human identity preserved;
- no destructive edit to the canonical raw/original;
- each source belongs to one or more explicitly listed DP IDs;
- do not include irrelevant images “just in case”.

## `LOGOS/` contract

Exact original client/partner logo files only.

Never include a screenshot or AI recreation when the real transparent/vector asset exists.

The image generator may use logos as a visual placement reference, but final production must verify that the exact original logo geometry is present. If generated logo treatment drifts, replace it in Canva/Adobe rather than accepting the drift.

## `STYLE_REFERENCES/` contract

Use approximately 3–6 deliberate references for the active brand scope where practical.

References should collectively demonstrate the client's visual grammar:

- typography behaviour;
- colour balance;
- gradients/effects;
- masking/cutout habits;
- photo treatment;
- visual density;
- logo attribution;
- quality/craft bar.

Do not select five examples of the same template. Do not mix unrelated sub-brand systems.

Reference screenshots are labelled with source Canva design/page metadata in the manifest or QA notes.

The generator must never infer which source belongs to which DP from file order alone.

## `PROMPT.txt` structure

The prompt is generated by the planning chat/system and should contain:

### 1. Batch role

State that this is a CG Production House monthly social-poster production batch and that every output must feel individually art-directed rather than templated.

### 2. Locked fidelity rules

- use supplied real client photography;
- preserve real-human identity and day-to-day permanent features;
- do not beautify/reconstruct faces/bodies;
- use exact supplied logos as reference and never invent/reinterpret them;
- use supplied brand colours and defined font behaviour;
- no fake AI-text texture in final intent;
- phone-first readability;
- no unsupported client facts.

### 3. Brand grammar

Describe what to learn from the supplied style references without copying their layouts.

### 4. Batch/grid direction

Demand intentional variation across:

- headline position;
- source crop/scale;
- light/dark balance;
- negative space;
- visual mechanism;
- texture/effects;
- subject/product/branch representation.

The batch must look coherent in an Instagram grid but not expose one repeated template.

### 5. Per-DP briefs

For every stable DP ID, state explicitly:

```text
ID
exact source filename(s)
brand scope / branch
primary job
audience/buying moment
proposition + proof
intended emotion/action
headline/copy direction
creative mechanism
distinctive assets required
recent/repeated ideas to avoid
```

### 6. Output discipline

Outputs are Wave 1 internal concepts. A strong creative composition may still require exact-font/logo finishing in Canva/Adobe. Do not treat generation completion as client approval.

## Two-pass production model

### Pass A — creative composition

Internal image generation is responsible for high-design visual thinking:

- composition;
- depth;
- gradient/light effects;
- masking/cutout interaction;
- hierarchy;
- texture;
- scale;
- editorial/advertising visual mechanisms.

### Pass B — fidelity/production finish

Canva/Adobe is responsible for exact production truth when required:

- exact font rendering;
- exact logo geometry;
- exact copy spelling/punctuation;
- exact brand colours;
- non-generative real-photo corrections;
- safe layer/compositing adjustments;
- editable handoff/export.

This split avoids throwing away the internal generator's stronger creative ability merely because exact typography/logo fidelity needs a deterministic finish.

## Wave 1 save contract

Candidate:

`YYYY_MM_CLIENT_DP_XX__W1_V01.png`

Store only candidates worth internal review. Do not put obvious failures into Approved.

Review:

- each poster individually at phone size;
- the whole batch together as a grid;
- against the strategy record, not just aesthetics.

## Amendment contract

Every failed candidate receives one failure class before work continues.

### `PRODUCTION_FIX`

Typography/logo/copy/spacing/brand colour/small alignment.

Route: Canva/Adobe. No regeneration.

### `SOURCE_FIX`

Photo crop/tone/blemish/cutout/fidelity issue.

Route: original source -> non-generative edit -> recompose only if needed.

### `CREATIVE_RESTART`

Weak strategy expression, generic design, wrong emotion, wrong hierarchy, repeated template mechanism, fundamentally wrong composition.

Route: fresh generation for only that DP from original edited source + exact references/assets + original strategy + correction delta.

Never use the failed generated bitmap as the sole source for a creative restart.

### `EFFECT_FIX`

Small glow/gradient/mask/effect issue that can be fixed cleanly.

Route: Canva/Adobe where practical.

## Correction-delta file

For a creative restart, save a small amendment record, e.g.:

`2026_11_PIEK_DP_03__W2_DELTA.txt`

It should say:

```text
What failed
Why it failed strategically/visually
What must remain from the original strategy
What must change
What must not be copied from the failed candidate
Source/assets to reattach
```

The new generation receives the original strategy plus this delta, not an accumulating chain of conversational edits.

## Approved/final contract

Creative approval and production approval are separate states.

Suggested states:

- `wave_1_review`;
- `creative_approved`;
- `production_finishing`;
- `production_approved`;
- `client_approved`;
- `scheduled`;
- `posted`.

Only `production_approved` or later may be treated as having exact typography/logo/source fidelity verified.

Approved flat:

`YYYY_MM_CLIENT_DP_XX__FINAL.png`

The exact Canva `design_id` + page identity is linked to the same `monthly_deliverables` item.

## Manual-designer compatibility

A human designer may skip the internal image generator entirely.

They still use:

- the same DP ID;
- the same strategy brief;
- the same freshness/source rules;
- the same `SOURCE_EDITED` assets;
- the same grid QA;
- the same Canva page linkage;
- the same usage ledger/writeback.

This is a production system, not an AI-only trick.

## Success criterion

A Chat Pack is ready only when another authorised CG staff member can open it, attach the supplied visuals to a normal ChatGPT chat, paste the supplied prompt, and understand exactly what is being made without asking the planning person which photo/logo/reference belongs to which poster.
